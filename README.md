# 🍃 LeafLens

**See Your Leaf Through a Smarter Lens.**

LeafLens is a React + FastAPI plant-leaf analysis application. It keeps a real OpenCV/scikit-image pipeline for detection, segmentation, contours, and shape, colour, and texture measurements, with optional trained models for species, health, and visible growth-stage prediction.

## Features

- Upload a JPG, PNG, or WEBP leaf image (drag/drop, preview, dimensions, 10 MB limit)
- Capture a leaf directly with a browser camera; the captured frame becomes the same `File` sent to `POST /api/analyze`
- Classical CV leaf detection with optional YOLO segmentation support
- Species classification, leaf health/disease classification, and visible growth-stage estimation when compatible real models are installed
- Shape, colour, texture, original, preprocessing, detection, mask, crop, and contour views
- SQLite-backed history, search, sorting, deletion, health filtering API, and dashboard health counts
- Responsive glassmorphism UI, light/dark/system themes, keyboard focus styling, and reduced-motion support

## User flow

```text
Image upload or camera capture
             ↓
Preprocessing → leaf detection → segmentation → crop
             ↓
┌────────────────┬────────────────┬─────────────────────┐
│ Species model  │ Health model   │ Growth-stage model  │
└────────────────┴────────────────┴─────────────────────┘
             ↓
Results → SQLite history
```

The browser camera requests `getUserMedia` with a preference for the rear camera on mobile. It must be used on HTTPS or `localhost`, and the user must allow camera access. Streams are stopped on close, capture, and unmount.

## Honest model availability

No fake predictions or confidence values are bundled. Until a trained model is installed, the relevant result is clearly shown as unavailable. The health feature is an image-based model prediction, not a professional plant pathology diagnosis; lighting, image quality, background, and model training coverage can affect results.

Health weights belong in `backend/models/health/best.pt` with real-run metadata in `backend/models/health/metadata.json`. The loader supports a serialized PyTorch model or the MobileNetV3 state-dictionary checkpoint generated by `backend/training/train_health.py`.

## Dataset guidance

Dataset roots are:

```text
backend/datasets/
├── leaf_types/       Mango, Neem, Guava, Rose, Hibiscus, Tulsi, Banana
├── health/           Healthy/ and Diseased/
└── growth_stages/    Early/, Developing/, Mature/, Senescent/
```

Use separate train/validation/test images, avoiding near-duplicate photos of a leaf across splits. Include relevant lighting, backgrounds, camera angles, species coverage, and disease coverage. Never represent the health model as identifying a disease or species that was not present in its evaluation data. See `backend/datasets/health/README.md` for the health dataset layout.

## Train the health model

Install the optional ML packages (`torch`, `torchvision`) and run:

```bash
cd backend
python training/train_health.py --data datasets/health
```

It uses MobileNetV3 transfer learning, augmentation, class-balanced loss, stratified train/validation/test splits, early stopping, a best checkpoint, held-out accuracy/precision/recall/F1, and a confusion matrix saved in real metadata. It does not write fabricated accuracy.

## Run locally

```bash
# terminal 1
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# terminal 2
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The frontend routes are Dashboard, Analyze, Results, and History. The API includes `GET /api/health`, `POST /api/analyze`, history endpoints, and dashboard statistics.

## Database compatibility

On startup, LeafLens adds nullable health columns to an existing SQLite `leaf_results` table only when they are missing. It does not delete or recreate the existing database, so historical analyses remain accessible.

## Train the leaf detector

The application already has a classical CV fallback. To install a real AI leaf detector, use a small YOLO **instance-segmentation** dataset with one class named `leaf` and export it in YOLO segmentation format.

Place the dataset at `backend/datasets/leaf_detection/` with a `data.yaml`, then from `backend` run:

```bash
pip install -r requirements.txt
python training/train_detector.py --data datasets/leaf_detection/data.yaml --epochs 50 --batch 8 --device 0
```

The script uses pretrained YOLO11n-seg and copies the evaluated best checkpoint to `backend/models/leaf_detector/best.pt`. The existing detector automatically loads that file on backend startup and otherwise keeps using the classical CV fallback.
